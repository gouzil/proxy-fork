# macOS E2E：2026-11-02

在 Apple Silicon macOS 上使用独立的 XDG 配置/数据目录、临时 CA、本地 HTTP/TLS 服务和 adhoc 签名 GUI 实测。没有覆盖日常 CA、私钥或配置。测试源代码基线为 `1340a190c80a01d66d203d98f59f8a3b7ab60228`，下文记录本轮修复与验证结果。

## 发现与修复

| 问题 | 实测证据 | 修复 |
| --- | --- | --- |
| 日常 CA 已过期，重新安装仍不能得到有效 HTTPS 信任 | 默认数据目录的证书 `notAfter=2026-10-07 16:31:05 UTC`，即北京时间 10 月 8 日 00:31:05；系统验证返回 `CSSMERR_TP_CERT_EXPIRED` | 安装前检查有效期，过期时明确要求移除记录并重新生成，在改动钥匙串之前返回错误。保留检查/移除过期 CA 的能力；未替换日常文件 |
| 删除钥匙串证书后仍残留用户信任 | GUI 删除测试证书后条目已消失，但对原证书文件执行 `security verify-cert -p ssl` 仍成功；仅比较 trust dump 会漏报 | 先显式撤销该证书的用户信任，再按已记录指纹删除条目；条目已不存在的重试也执行撤销 |
| 停止会被未完成 HTTP 响应卡住，CONNECT/WebSocket 在停止后仍存活 | 三项真实 socket 回归分别复现停止超时、隧道未关闭、WebSocket 未关闭；旧 GUI 停在“正在停止”，系统代理未及时恢复 | 在共享 hudsucker 层把升级任务纳入关闭管理，停止时取消；普通 HTTP 优雅退出最多等待 2 秒 |
| CLI 自定义 CA 路径静默覆盖已有文件 | 重复 `gen-ca --ca-cert … --ca-key …` 后文件被替换，未询问 | 自定义路径与默认路径使用同样的覆盖确认；两个文件确认完成前不写入 |

## 已完成的验证

- GUI 真实生成并安装临时 CA，经人工完成系统授权后，原生 `/usr/bin/curl` 不指定 `--cacert` 即可通过代理访问 HTTPS 改写规则，响应来自本地目标服务。
- 关闭 CA 后，HTTP 转发和 HTTPS CONNECT 到本地 TLS 源站均通过。
- GUI 无效端口检查、活动 HTTPS 规则、系统代理接管均实测；旧版停止卡住后，隔离 GUI 重启恢复了原始系统代理。
- 修复后的 GUI 在真实系统代理开启、HTTP 响应只返回部分正文时点击停止：连接在约 **2.14 秒**后断开，界面返回“已停止”，监听端口关闭；9 份网络服务代理字典及当前有效代理均恢复测试前值，恢复日志文件已清除。
- 实际调用修复后的 CA 移除函数，人工完成撤销授权；系统验证返回 `CSSMERR_TP_NOT_TRUSTED`，其他钥匙串证书指纹保持原样。
- 新增回归均先在旧代码失败，再在修复后通过：CLI 覆盖确认（EOF、拒绝、部分同意、全部同意）、HTTP/CONNECT/WebSocket 停止、过期 CA 安装前拒绝。实际信任撤销回归默认忽略，只能显式提供已授权的测试 CA 执行。
- Rust 1.90.0：全工作区 **129 passed / 0 failed / 7 ignored**；另行显式运行真实 CA 撤销回归 **1 passed**。GUI/CLI debug 构建、格式检查和 `git diff --check` 通过。
- 工作区 all-target Clippy 通过，保留原有 `main.rs:648` 的一项 `collapsible_if` 风格警告；不宣称严格零警告。
- 清理后再次确认：临时 CA 不受信任，其他钥匙串证书指纹未变，系统代理恢复原样；所有测试进程和监听端口关闭，三份临时私钥已删除，记录在 `cleanup-final.json`。
