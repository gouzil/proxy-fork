# macOS GUI 验证与恢复清单

本次交付是本机可运行的 ImGui 桌面预览，不是已经签名、公证并通过全部硬件验收的正式发行版。原生系统操作只实现 macOS；Windows/Linux 的通用界面由 CI 配置覆盖，但尚无本次远端运行结果。

## 运行与隔离

```bash
cargo run --locked -p proxy-fork-gui
```

四个主页面：概览（状态控制）、规则管理、日志、设置；CA 与更新使用独立对话框，不额外算主页面。固定侧栏与卡片布局参考 Clash Verge；概览宽屏双列，小窗口单列滚动，保存入口固定在顶部；各页面独立保留滚动位置。卡片标题、说明、字段与操作按钮统一靠左，按钮文字居中，卡片操作不再铺满宽度。侧栏仅显示放大的 Proxy Fork，与导航文字左边缘对齐；导航紧跟品牌文字排列，不再为已删除的副标题留空。首次启动不自动启动代理，系统代理与自动检查更新默认关闭。默认 HTTPS 拦截需要先生成/选择 CA；只测试 HTTP 转发时取消 CA 开关。

设置 → 应用设置 → 主题模式提供“浅色 / 深色 / 系统”三段选择，系统即跟随系统，也是默认值。选择立即应用到窗口、卡片、表格、弹窗及原生标题栏，并自动保存到 `gui.toml` 的 `theme = "system" | "light" | "dark"`；旧配置缺少该字段时按跟随系统处理。忙碌期间的修改会在当前操作结束后保存，原操作失败也不漏存；自动保存失败时保留原错误并追加保存错误，不无限重试。跟随系统响应原生外观事件，手动模式不被系统变化覆盖；平台无法读取系统外观时回退为浅色。

设置页使用系统、应用、更新三张卡片；宽屏左侧系统/更新、右侧应用，小窗口按系统/应用/更新顺序单列滚动。标签在左、控件在右，统一行高与内边距；语言为下拉框，登录启动与自动检查为开关。保留保存偏好、手动检查及原有错误恢复入口，不增加 Clash 专有功能。

侧栏底部只显示“本地服务”、运行状态和版本号，与品牌及导航文字左边缘对齐；三行紧凑排列，按实际行高定位并保留底部留白。底部不再提供“退出”按钮，托盘里的退出入口保留。

设置中的“登录后自动启动”采用左侧标题、右侧圆角开关，替代常驻的状态说明和启用/停用/刷新按钮；状态及下次登录生效说明可悬停查看。空闲进入设置时只读检查一次，点击开关后以系统返回结果更新状态，不提前假定成功。未知状态点击仅重新检查；若已出现读取错误，点击打开刷新/启用/停用恢复选项，避免旧注册路径失效后无法修复。忙碌或不支持的平台不可切换；本轮自动测试只断言 UI 动作，没有实际启停登录项。

打开证书管理时，只有默认 CA 文件不存在会显示“尚未配置”及生成入口，不自动生成、安装或信任。自定义路径不存在、证书损坏和权限错误仍显示错误；重新检查前撤销旧指纹的确认状态，保留已记录的证书所有权。

GUI 只读取用户配置，不读取当前目录的 `proxy-fork.toml`。macOS/Linux 默认使用 `~/.config/proxy-fork/{config,gui}.toml`，状态目录为 `~/.local/share/proxy-fork`；尊重 `XDG_CONFIG_HOME`、`XDG_DATA_HOME`。私钥不进入 GUI 偏好。

推荐隔离测试，禁止把下面的临时配置与日常代理配置混用：

```bash
gui_smoke_dir="$(mktemp -d /private/tmp/proxy-fork-gui-smoke.XXXXXX)"
XDG_CONFIG_HOME="$gui_smoke_dir/config" \
XDG_DATA_HOME="$gui_smoke_dir/data" \
cargo run --locked -p proxy-fork-gui
```

关闭窗口只隐藏；应通过托盘的“退出”结束应用。若系统代理恢复失败，窗口保留错误，不自动退出。SIGINT/SIGTERM 也进入 GUI 的退出流程；SIGKILL/断电不能即时清理。

macOS 系统代理现在使用 SystemConfiguration 原生字典及服务 UUID，不使用 `sysproxy` 的合并元组。只把 HTTP/HTTPS 指向本应用，不把 HTTP 监听器误设为 SOCKS；其他字段保留并在结束时恢复。接管期间暂停已开启的 PAC/自动发现，并在恢复时还原。遇到认证/用户/密码字段时拒绝接管，不复制凭据。提交/应用的原生返回值必须成功，且再次读取相符后才能删除恢复记录。

登录项禁用使用 `launchctl disable` 并移除 plist，不对启动当前 GUI 的 job 执行 `bootout`；已加载任务的路径变更在下次登录生效。程序搬家后应重新启用以更新注册路径。

## 故障恢复

1. 优先在应用中“停止/退出”，查看完整错误；不要先删除 `system-proxy-restore.toml`。
2. 冲突时读取记录里的 `service_id` 与 `original.proxies_xml`，在系统设置的对应网络服务中逐项核对。不要把当前活动服务当成原服务，也不要用单个 `sysproxy` 元组覆盖所有协议。
3. 权限拒绝时保留记录，授权后重试。外部修改的目标状态需要测试者自行决定，应用不会强行覆盖。
4. CA 覆盖采用私钥备份加失败回滚；如果操作系统连回滚也拒绝，错误会给出保留下来的旧私钥备份路径，先恢复配对文件，不要继续签发。
   Keychain 修改前先保存候选指纹；信任失败后仍可刷新状态并清理候选证书。先移除旧 CA 信任，再生成覆盖文件或信任另一个指纹。
5. 新版启动失败会还原并重新打开旧版；如果旧版也无法启动，从同目录 `.previous-<pid>.app` 手工恢复，保留失败现场。首次 target→backup 改名失败时旧应用保持原位，但当前 helper 不自动重开它，须人工打开；这一安装失败分支及真实签名更新仍待完整验收。

## 资源占用的复测方法

使用 release `.app`、隔离配置，不启用代理、更新或文本编辑计时器。通过 `ps -p <pid> -o pid,rss,%cpu,time,etime` 在间隔至少一分钟的两次采样中比较 RSS 与累计 CPU 时间。退出日志包含实际帧数和 font atlas 字节数；分别记录无输入可见启动与 `--background` 隐藏启动，不能把启动帧算成持续重绘。

另行测试持续日志、中文编辑/IME 和代理负载；通过 Activity Monitor / Instruments 测 GPU、能耗与 CPU，不用 `ps` 的 0.0% 推断 GPU 为零。记录机器型号、OS、缩放、采样时长、并发负载与构建版本。当前只有开发机观察，没有干净 macOS、混合 DPI 或 GPU/能耗的验收结论。

Dear ImGui 缺少完整的原生辅助功能树；键盘导航不等于 VoiceOver 支持。
